# Tool Library Map

The Tools Library contains reusable student-facing processes.

Tools should be simple, clear, and tied to action. They should help students think, study, reflect, or prepare with less friction.

Do not create tools just to make the app feel interactive.

A tool should exist only when it gives students a structure they can return to more than once.

---

## Tool Rules

A tool must do at least one of the following:

- reduce cognitive load
- support clinical reasoning
- guide reflection
- help students turn feedback into action
- make learning more usable under pressure
- help students organize knowledge so it can be used later
- support safer decision-making under uncertainty
- help students test whether study methods are producing usable access
- help students shape recall so it supports clinical use

Tools should stay short. If a tool needs a long explanation, the concept probably belongs in a section first.

A section does not need a tool to be useful.

A tool should not appear in a section just because the interface allows it.

### Smart Note Template

Status: Draft v1, active core tool

Use when:  
A student needs to turn a concept, scenario error, confusing idea, or repeated feedback point into a reusable thinking note.

Purpose:  
Help students build notes that support thinking rather than simply store information.

Fields:

- Claim
- Explanation
- Clinical signals
- Common confusion
- Links

### Directive Meaning Check

Status: Draft v1, active core tool

Use when:  
A student is learning or applying a directive and needs to understand what the directive is protecting, supporting, or preventing.

Purpose:  
Help students understand directive intent so directives become easier to apply safely, explain clearly, and reassess appropriately.

Questions:

- What clinical risk is this directive protecting against?
- What physiology is being supported or protected?
- Where are the firm boundaries?
- What would make me withhold, stop, patch, or change course?
- What should I reassess afterward?

Related sections:

- [[Directives Through Purpose]]
- [[Meaning Before Memorization]]
- [[Pathophysiology Through Patterns]]
- [[Clinical Reasoning]]
- [[OSCE Preparation]]

Related active tool:

- [[Clinical Recall Prompt Builder]]

Notes:  
This tool is active because [[Directives Through Purpose]] created a repeated need for a reusable directive-learning structure. It should support safer interpretation, not loosen standards or encourage casual protocol use.

The relationship with [[Clinical Recall Prompt Builder]] is useful because directive details can become recall prompts, but [[Directive Meaning Check]] remains the primary tool for understanding purpose, risk, boundaries, and reassessment.

### Clinical Recall Prompt Builder

Status: Draft v1, active core tool

Use when:  
A student needs to turn a fact, note, scenario error, directive detail, or confusing concept into recall prompts that support clinical use.

Purpose:  
Help students shape recall around assessment, decisions, boundaries, reassessment, and communication instead of practicing only isolated trivia.

Builder structure:

- What am I trying to remember?
- What clinical job does this knowledge do?
- Make one basic fact prompt.
- Make one clinical cue prompt.
- Make one decision or boundary prompt.
- Make one reassessment prompt.
- Optional: make one communication prompt.

Related sections:

- [[Retrieval and Spaced Learning]]
- [[Clinical Recall Without Trivia]]
- [[Anki for Paramedic Learning]]
- [[Smart Notes for Paramedic Students]]
- [[Types of Notes and Idea Maturation]]
- [[Directives Through Purpose]]
- [[Clinical Reasoning]]

Related active tools:

- [[Smart Note Template]]
- [[Directive Meaning Check]]

Notes:  
This tool is active because the Build Recall cluster repeatedly returns to the same practical need: students need to practice remembering information in a form that can support patient care.

It should not become an Anki-specific tool, deck-management system, or flashcard tutorial. It may support Anki, but its purpose is broader than Anki.

### Five Whys Tool

Status: Planned core tool

Use when:  
A repeated error or meaningful decision needs deeper review.

Purpose:  
Help students trace an error back to a learning structure rather than stopping at surface behaviour.

Steps:

- Choose one moment.
- Ask what led to it.
- Continue until the answer points to learning structure, not only behaviour.
- Stop when there is one actionable adjustment.

Related sections:

- [[The Five Whys]]
- [[Common Errors and What They Reveal]]
- [[Turning Feedback Into Action]]
- [[Reflection Without Journaling]]

Notes:  
Do not draft this tool until the Reflect and Improve cluster is rebuilt, unless the Five Whys section clearly earns it earlier.

### Cognitive Load Check

Status: Possible future tool

Purpose:  
Help students identify one moment in a scenario where their thinking became crowded and name what was competing for attention.

Use when:  
A student misses something they knew, loses track of priorities, fixates on a task, or feels behind during a scenario.

Possible questions:

- Where did my thinking become crowded?
- What was competing for attention?
- Was I trying to remember a sequence, make a decision, perform a skill, or manage uncertainty?
- What support would reduce that load next time?
- Does this need better structure, better understanding, better retrieval, or more practice?

Related sections:

- [[Cognitive Load]]

- [[OSCE Preparation]]
- [[Performance Under Pressure]]
- [[Reflection Without Journaling]]

Notes:  
Do not build this yet. The idea is embedded in [[Cognitive Load]] for now and may become reusable later if it appears across scenario, OSCE, and reflection sections.

## Tool Placement Notes

Tools should be available in two ways:

1. Connected to relevant sections when they support the reading.
2. Collected in the central Tools Library for later return.

Tools should not interrupt conceptual sections unless they introduce a practical process students can reuse.

In the first app slice, active tools may be tested as standalone pages, section-linked drawers, or both.

Current likely contextual placement:

- [[Directive Meaning Check]] may appear with [[Directives Through Purpose]].
- [[Smart Note Template]] may appear with [[Smart Notes for Paramedic Students]], [[Types of Notes and Idea Maturation]], and [[Obsidian for Learning Paramedicine]].
- [[Clinical Recall Prompt Builder]] may appear with [[Clinical Recall Without Trivia]] and [[Anki for Paramedic Learning]].
- [[Clinical Recall Prompt Builder]] may be related to [[Retrieval and Spaced Learning]], but does not need to appear as a drawer there.

Final interface decisions should be confirmed during the app-readiness checkpoint and tested in the first vertical slice.
