# VitalNotes Rebuild Master Map

## What VitalNotes Is Now

VitalNotes is a student-facing learning guide for paramedicine.

It helps students understand how learning behaves under the conditions of paramedic training:

- cognitive load
- uncertainty
- pressure
- scenario performance
- OSCE evaluation
- memory and retrieval
- note-making
- reflection
- clinical reasoning
- directive interpretation
- performance under pressure

VitalNotes teaches students how to learn paramedicine, not how to memorize more content.

It is not a generic study skills blog.

It is not a protocol summary.

It is not a motivational site.

It is not an app full of busywork.

It is a guided learning system grounded in paramedic education.

## Why We Are Rebuilding

The old VitalNotes material contains strong ideas, but the structure grew outward as sections were developed.

The rebuild will:

- reduce repetition
- sharpen the learning arc
- preserve the strongest explanations
- make the guide easier to navigate
- organize content around student problems
- prepare the material for an app-style interface
- support glossary terms, tool drawers, and cleaner section flow

The goal is not to preserve the old site structure.

The goal is to preserve the strongest thinking and reorganize it into something clearer, smaller, more usable, and more navigable.

## New Content Logic

The new guide should be organized around student problems and learning needs, not only around concepts.

Example:

Student problem:

"I study, but I blank in scenarios."

Underlying concepts:

- cognitive load
- retrieval
- pressure
- recognition
- access
- working memory

Student-facing sections:

- [[Why Studying Feels Productive But Fails Under Pressure]]
- [[Retrieval and Spaced Learning]]
- [[Clinical Recall Without Trivia]]

Related tool:

- [[Clinical Recall Prompt Builder]]

This logic should guide all future sections.

Students should be able to recognize the problem before they are asked to understand the concept.

## Current Working Rule

If a new idea appears, place it in the vault before building around it.

If an idea does not clearly belong in the current content map, park it.

If a feature does not help students read, navigate, understand, use a tool, or continue learning, do not build it yet.

If a section does not solve a real student problem, it needs more work.

If the app becomes more interesting than the learning, it is drifting.
